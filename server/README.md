# Momentum optional online service

The app's local preparation, profile, practice, application drafts and offer tools work without this service. This Node service adds public job-page import, optional OpenAI coaching, and separately enabled public professional company/interviewer research. It does not apply for jobs, access LinkedIn or Indeed accounts, research people without a specific opt-in request, or store candidate content.

Use Node 24.5 or later. No runtime packages are needed. Start locally with `npm run server`; the default address is `http://127.0.0.1:8787`. Vite can proxy `/api` to this address. `GET /api/health` reports actual capabilities, so an absent API key never appears as working online coaching.

For environment-file configuration, copy `server/.env.example` to `server/.env`, populate only the settings you need, and run `node --env-file=server/.env server/index.js`. Keep that file out of source control. Never put API keys or service tokens into a `VITE_` variable, frontend bundle, mobile binary, local storage or backup.

For a same-origin production build, run `npm run build` and set `PRISM_STATIC_DIR` to the resulting `dist` directory. The Node process then serves both the app and `/api` with MIME validation, restricted static paths, security headers and appropriate cache policies. The multi-stage `Dockerfile` builds this layout into a non-root runtime without development dependencies. `deploy/compose.yaml` puts Caddy in front for automatic HTTPS while keeping the app port private. See [the deployment guide](../docs/deployment.md) for operator setup. Nothing is publicly deployed by these files.

## Endpoints

`GET /api/health` returns `ok`, `version`, `capabilities: {jobImport, aiCoach, webResearch}`, `model`, and non-secret `privacy` metadata. `privacy.storesContent: false` describes this service's code only, not hosting or provider retention.

`GET /api/ready` returns the same shape, with `ready: true` only after any configured static app build was found. It returns 503 if that build is absent. Health remains a liveness check; readiness does not verify an external website, OpenAI credentials, a gateway, public policies, or Apple distribution. `node server/healthcheck.js` is the container probe. `node server/smoke.mjs https://your-real-host` checks the app, API, headers, asset MIME/cache behavior and denied private paths without calling any external provider.

`POST /api/import-job` accepts `{url}`. It returns `{job: {text, role, company, url, source}, warnings}`. `source` is `job-posting` when a Schema.org JobPosting is extracted, otherwise `page`. The client must present imported content for review. Some sites require JavaScript, authentication, or block automated access; pasting text remains the fallback. This endpoint imports only the supplied page and follows at most three redirects. It is not a web-search API.

`POST /api/coach` accepts `{consent: true, action, job, profile, question, answer, context}`. Actions are `course`, `interview-feedback`, `application`, `research`, and `negotiation`. `job` is `{role, company, text}`; profile and context are bounded JSON values. A feedback request needs a question and an answer of at least 20 characters. The client must explicitly disclose OpenAI and the information being sent before obtaining consent. A previously configured API key does not substitute for consent.

The transfer limit is 450,000 bytes, including JSON encoding. Job text, individual profile/context strings and résumé text support up to 60,000 characters; practice answers support 20,000. The complete normalized coaching input is limited to 140,000 serialized characters. A full-size job and résumé plus ordinary lesson context fit, including non-ASCII text. Larger combinations are rejected with an actionable message, never silently truncated. Course coaching extends `context.lesson` when present and respects the supplied intake/time budget; research notes remain unverified source material.

Coaching returns `{result: {title, summary, sections: [{title, body, bullets}], nextSteps}, provider: "openai"}`. Render all strings as text, never trusted HTML. Results are coaching suggestions, not verified employer facts or hiring predictions. Without a separate web-research request, the `research` action only organizes supplied professional/public information and has no browser or search tool.

For opt-in public research, set `PRISM_ENABLE_WEB_RESEARCH=true` on the service and use an OpenAI model that supports both the Responses `web_search` tool and structured output. Normal AI key and production authorization requirements still apply. The capability is **off by default**. A client must separately disclose that the company/interviewer details, job description and research notes go to OpenAI and that professional search terms may go to its web-search providers, then send `action: "research", consent: true, webResearch: true`. The company name is required. This permission applies to the specific request; it must not silently follow from ordinary coaching consent.

This branch uses the web-search tool for public company/team pages, professional bios, publications, talks and relevant professional news. It instructs the model to avoid private life, sensitive characteristics, contact details and identity guesses. It excludes the candidate profile and practice answer from the provider payload. Job description and research context are still sent to OpenAI; keep those notes focused on public professional material. Search queries are constrained by instructions to professional names, organizations, roles, URLs and relevant public work. Prompt constraints are not a substitute for provider/privacy review.

A successful research response adds `sources: [{title, url}]` and `research: {requested: true, completed: true}`. Sources come **only** from URL-citation annotations in the provider response, not from generated source strings. Links must use public HTTPS URL syntax. The service requires a completed web-search tool call and at least one usable citation, otherwise it returns `RESEARCH_UNVERIFIED` (502). Render the links beside the result and invite users to verify identity, dates and context. Citations show where the model sourced information; they do not independently prove the claims are correct. `RESEARCH_NOT_CONFIGURED` (503) means the installation has not enabled this optional capability. Existing coaching responses retain their original shape.

Errors use `{error: {code, message}}` and a suitable HTTP status. Notable codes are `COACH_NOT_CONFIGURED` (503), `CONSENT_REQUIRED` (400), `AUTH_REQUIRED` (401), `ORIGIN_DENIED`/`HOST_DENIED` (403), `RATE_LIMIT` (429), and import errors with a paste-text fallback. There is no simulated success on service failure.

## Production requirements

- Terminate TLS at a trusted reverse proxy, use a dedicated service process, and configure the exact app origins in `PRISM_ALLOWED_ORIGINS`. Native iOS calls use `capacitor://localhost` and must be explicitly allowlisted. Configure your real operator name, privacy URL and support contact.
- The listener binds to loopback by default. If you change `HOST` to `0.0.0.0`, use a firewall or private service network. Public domain Host headers must correspond to a configured allowed origin. Do not expose a development service on an untrusted network.
- Online coaching is disabled in `NODE_ENV=production` unless both `OPENAI_API_KEY` and `PRISM_SERVICE_TOKEN` are configured. A configured service token protects **both** POST endpoints. Use a cryptographically random token, kept only on a trusted gateway. That gateway must authenticate the individual app user and inject the token upstream. Do not ship a shared token to every client. User authentication, entitlements, billing and an authenticated gateway are not implemented by this reference service; deploying paid online coaching remains blocked until they exist.
- API keys stay server-side. OpenAI requests use the Responses API with structured output and `store: false`. That setting does not mean zero provider retention or zero abuse-monitoring retention. Verify the provider account's current terms, configure your retention choices, and publish an accurate privacy disclosure before launch. If web research is enabled, include OpenAI’s search providers/subprocessors, query disclosures and search pricing in that review.
- Request bodies and response bodies are not logged or persisted by this service. The application does not retain an OpenAI response identifier. Your hosting provider, reverse proxy and OpenAI may retain metadata or content under their own configuration and terms. Review those separately; do not enable request-body logging.
- Per-client limits are 25 imports and 10 coaching calls per 10 minutes. Global limits are 300 imports and 60 coaching calls per 10 minutes. Counters use the TCP peer address and ignore forwarded IP headers; configure additional authenticated per-user quotas at the gateway. In-memory limits reset on restart and are not a distributed billing safeguard.
- Expensive work is bounded to four concurrent imports and two concurrent coaching requests per process. Excess work gets `SERVICE_BUSY` (503) instead of an unbounded queue. HTTP headers/body timeouts and socket request limits bound slow clients. Shutdown allows up to ten seconds for in-flight work before closing connections. Local saved work is not held by this process.

## Network boundaries

Imports accept public HTTPS hostnames only, on port 443, without embedded credentials. They resolve DNS, reject every private/special address, pin the validated public IP for the request, and repeat validation after each redirect. Responses have 12-second total, 2 MiB transfer/decompression, and 60,000-character output limits. Imported text is data, never service instructions. Both HTML and JSON-LD are parsed conservatively without executing scripts.

Direct pinned requests intentionally bypass inherited HTTP proxies. Set `PRISM_TRUST_ENV_PROXY=1` **only** when an operator-controlled outbound proxy independently denies private/internal destinations and DNS rebinding. CONNECT proxies resolve destination names themselves, so application-side pinning cannot provide that guarantee in proxy mode. The managed Codex environment's policy-enforcing egress proxy meets that requirement for development testing. API calls to the fixed OpenAI host preserve inherited proxy and certificate settings. TLS certificate validation is never disabled.

## Validation

Run `node --test tests/server.test.js tests/server-deployment.test.js`. Tests cover private-address and encoded-IP rejection, mixed DNS answers, redirect revalidation, malformed pages, structured extraction, CORS and native origins, local DNS rebinding, consent, payload limits, rate limits, authentication, and mocked OpenAI coaching/web-search contracts. Deployment tests cover static traversal/symlink denial, cache/MIME/security headers, readiness, bounded concurrency and Unicode input limits. Research tests cover separate opt-in, disabled capability, candidate-field exclusion, actual tool-call evidence, and provider citation validation. A successful live public-page import was checked in the managed environment. No live AI or web-search call has been verified without an operator-supplied key; a passing mock is not a live-provider test. Confirm model/tool compatibility, citations, provider behavior, latency and search costs against the live account before enabling research for users.
